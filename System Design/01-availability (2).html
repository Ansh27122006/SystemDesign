01 · The problem

What actually breaks availability

Availability isn't just "the code has no bugs." It's a war on many fronts. Anything that stops a request from getting a response counts.

🔌

Hardware failure

Disks die, RAM fails, power supplies burn out — silently, at 3am.

🌐

Network partition

The server is alive, but nothing can reach it. Same effect as being dead.

📈

Traffic spike

A sudden surge (sale, viral post) overwhelms capacity and requests queue up or drop.

🚀

Bad deployment

A new release ships a crash bug. Every instance running it goes down together.

🌪️

Natural disaster

A single data center can be taken out by fire, flood, or a regional outage.

🧑‍🔧

Human error

Misconfigurations and fat-fingered commands cause a huge share of real outages.

02 · The fix

Redundancy + load balancing

One server is a single point of failure. Put several behind a load balancer, and the health check quietly routes around anyone who goes down. Try killing servers below, then send a wave of requests.
