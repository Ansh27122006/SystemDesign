SYSTEM DESIGN LAB · MODULE 03

Availability vs Consistency

The CAP theorem, in plain terms: a network Partition (a break in communication between nodes) is inevitable in any distributed system. When it happens, you must choose — keep answering requests (Availability) or guarantee every answer is correct (Consistency). You cannot fully have both at the same time.

Opening analogy — two bank branches, one phone line down

Normal operation: both branches can call each other to confirm your balance before approving a withdrawal. Every answer is instant and correct.

01 · CORE DEFINITIONS
What CAP is actually asking

CAP stands for Consistency, Availability, Partition tolerance. Partitions will happen — cables get cut, data centers lose connectivity, packets get dropped. So the real, practical choice is between C and A whenever P occurs.

Availability (AP)

Every request that reaches a working node gets some response, even during a partition — even if that response might not reflect the most recent write.

🏦 Analogy: the branch keeps serving customers using its own local records, even though it can't reach the other branch to double-check.
always respondseventual consistencyDynamoDB, Cassandra
VS

Consistency (CP)

Every read reflects the most recent write, everywhere. During a partition, a node may refuse to answer rather than risk returning stale or conflicting data.

🏦 Analogy: the branch refuses withdrawals it can't verify with the other branch until the phone line is restored.
refuses when unsurestrict consistencytraditional SQL, ZooKeeper

05 · REAL-WORLD EXAMPLES
How real products make this call
🏦

Bank transfers

Moving money between accounts favors consistency. Showing a stale balance, or letting the same $100 be withdrawn twice from two disconnected replicas, causes real financial harm — so the system would rather reject the transaction than risk it.

CONSISTENCY (CP)
🌍

DNS

DNS is designed to always answer, even with a slightly stale record — that's exactly what TTLs (time-to-live) are for. An unreachable DNS server breaks the entire internet for its users, so availability wins decisively here.

AVAILABILITY (AP)
🛒

Shopping cart (Amazon Dynamo)

Amazon's original Dynamo paper explicitly chose availability for the shopping cart: it's far better to let a customer add an item (and merge conflicting cart versions later) than to block them from shopping because two data centers can't sync right now.

AVAILABILITY (AP)
📦

Inventory / stock counters

Systems that track exact stock (airline seats, limited-drop sneakers) favor consistency — overselling the last unit to five different disconnected customers causes real fulfillment problems and angry customers.

CONSISTENCY (CP)
06 · COMMON CONFUSIONS
What students usually get wrong
✕
"You can just pick C, A, and P — pick all three."

Partition tolerance isn't really optional — networks fail. The real trade-off only kicks in during a partition: you choose C or A for that window of time, not all three, all the time.

✕
"A CP system is never available and an AP system is never consistent."

Both statements are false. A CP system is fully available during normal operation (no partition) — it only sacrifices availability during a partition. An AP system is usually consistent too — it just tolerates temporary staleness instead of blocking.

✕
"This is a permanent architecture decision for the whole system."

Many real systems mix both — e.g. an e-commerce site might be AP for browsing/cart and CP for the final payment step, because the cost of being wrong is different for each.

07 · IN-CLASS ACTIVITY
CP or AP?
GRADED

Pick the right side of the trade-off

For each system, decide whether it should favor consistency or availability when a partition hits.

1. A bank's system processing money transfers between accounts.
Favor consistency. Showing the wrong balance, or allowing a double-spend during a partition, is worse than the system briefly refusing a transaction.
2. A social media "like" counter shown under a post.
Favor availability. If the like count is off by a few for a moment, nobody's harmed — but the feed going down entirely would upset every user.
3. DNS — translating a domain name to an IP address.
Favor availability. DNS always answers, even with slightly stale records — an unreachable DNS server breaks the internet for its users.
4. A distributed lock service used to make sure only one server at a time can process a critical job.
Favor consistency. If two disconnected nodes both believe they hold the lock, you get duplicate processing — the entire point of a lock is a single, agreed-upon truth, so it must refuse rather than guess.
