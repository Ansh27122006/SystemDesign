Load Balancing Lab

Three live models. Poke them, break them, and watch what happens.

Servers and keys share one ring

Each key walks clockwise to the first server it meets. Add or remove a server and only the keys in the affected gap move.

Change the servers to see how many keys move.
  • Add a server: only keys just before it move to it.
  • Remove one: its keys slide to the next server clockwise.
  • Compare with plain hash mod N, which reshuffles almost everything.

Probe, mark, reroute, recover

Requests (blue) go only to servers marked healthy. Probes (purple) test each server. A server is marked unhealthy after 2 failed probes and healthy again after 2 passes.

  • Crash a server. Watch a few requests fail before it is marked unhealthy.
  • Pick a 5 s interval: detection gets slower, more requests fail.
  • Recover it and watch it rejoin after 2 passes.

Send users to the best region

Click the map to drop a user. The GSLB picks the closest region that is healthy and not full.

    • Click near Asia: lowest latency wins.
    • Fail Asia, click there again: traffic shifts.
    • Click rapidly in one spot: the region fills and overflows.
