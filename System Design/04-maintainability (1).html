Maintainability

Six months from now, someone who didn't write this code has to fix it, extend it, and keep it running at 3am. How easy have you made that?

00 · The three pillars

What "maintainable" actually means

It's not one thing — it's three separate qualities that all need attention.

🛠️

Operability

How easy is it to keep the system running smoothly day-to-day — monitoring, deploying, debugging?

🧩

Simplicity

Can a newcomer understand a piece of it without holding the entire system in their head at once?

🌱

Evolvability

Can you safely add a new feature next year without secretly breaking three old ones?

Q1. In the Blast Radius game, why did the monolith break 4 features from 1 change?
Because monoliths always have more bugs
Because everything shares the same code and state with no isolation between features
Q2. What does "technical debt" cost a team over time, based on the snowball simulation?
Nothing, as long as tests still pass
Delivery velocity — each sprint gets slower as shortcuts pile up and demand rework
Q3. Why did the "no monitoring" team take so much longer to fix the same bug?
They had to guess and manually check each system one by one instead of seeing exactly where the problem was
Their code was written in a slower language
Q4. What made the documented codebase faster to onboard onto in the race?
It had fewer total features to learn
Clear docs and modular structure meant less time stuck asking around for tribal knowledge
