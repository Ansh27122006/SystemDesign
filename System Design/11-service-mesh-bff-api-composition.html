Service Mesh, BFF & API Composition

Once a system has enough microservices, three new problems show up: how do services talk to each other reliably and securely (Service Mesh), how do wildly different client apps get the API shape they each need (BFF), and how does a client get data that's scattered across several services in one trip (API Composition)?

01 · THREE PATTERNS, THREE DIFFERENT PROBLEMS
Where each one sits in the system

These solve different layers of the same underlying pain point: a microservices system has a lot of moving parts, and someone needs to manage the wiring between them.

Service Mesh

Infrastructure that handles service-to-service communication — retries, encryption, load balancing, observability — without any application code changes.

internal trafficsidecar proxiesIstio, Linkerd

Backend for Frontend (BFF)

A dedicated backend layer per client type (mobile, web, partner), shaping and aggregating data exactly how that client needs it.

client-facingone per client typeNetflix, Spotify

API Composition

Combining data from multiple services into a single response, so a client makes one request instead of several.

data aggregationparallel fan-outGraphQL federation

06 · COMMON CONFUSIONS
What students usually get wrong
✕
"A service mesh and an API gateway are the same thing."

Different layers. An API gateway handles traffic coming into the system from outside ("north-south" traffic); a service mesh handles traffic between internal services ("east-west" traffic). Many systems use both.

✕
"A BFF duplicates all the business logic for each client."

A well-built BFF is a thin aggregation and shaping layer, not a reimplementation of business rules — the actual logic still lives in the underlying services; the BFF just adapts the shape of the response.

✕
"API composition is just another name for an API gateway."

A gateway typically routes one request to one service. Composition specifically means combining data from multiple services into a single response — a meaningfully different job, even though a gateway or BFF often does both.

07 · IN-CLASS ACTIVITY
Which pattern solves this?
GRADED

Service Mesh, BFF, or API Composition?

For each problem, pick the pattern that solves it best.

1. Every one of 40 microservices has its own, slightly different, hand-written retry and timeout logic — and half of them get it wrong.
Best fit: Service Mesh. A mesh applies consistent retry, timeout, and encryption policy across every service automatically, without each team reimplementing it themselves.
2. The mobile team keeps asking the API team for a smaller response payload, while the web team keeps asking for more fields — on the same endpoint.
Best fit: BFF. Each client type gets its own tailored backend, so mobile and web stop fighting over the shape of one shared endpoint.
3. A single dashboard screen needs data from 5 different services, and today the browser makes 5 separate slow round trips to load it.
Best fit: API Composition. One composer service fans out to all 5 services in parallel and returns a single merged response, cutting 5 round trips down to 1.
4. Security wants every internal service-to-service call encrypted (mTLS), without asking every team to add encryption code to their own service.
Best fit: Service Mesh. Encrypting all internal traffic transparently, without touching application code, is one of a service mesh's signature capabilities.
