Reliability

The probability a system performs correctly over a given period, without failing. It's not the same as availability — a system can be "up" and still return wrong or failed results. Watch how retries hide raw failures from the user without actually reducing how often they happen underneath.

Reliability vs. Availability

These two get mixed up constantly. They measure different things, and a system can score well on one and poorly on the other.

Question it answersExample
AvailabilityIs the system reachable right now?The API responds to requests 99.95% of the time.
ReliabilityDoes the system behave correctly, without failing, over time?Out of 10,000 requests handled, 40 returned wrong or failed results.
Why this distinction matters: raising the failure-rate slider above and enabling retries keeps "success rate" high — the system looks reliable from the outside. But raw failures keeps climbing underneath. Retries are a real technique (used everywhere, from HTTP clients to database drivers) but they mask a root cause; teams that only watch user-facing metrics can miss a degrading dependency until retries stop being enough to cover for it.
